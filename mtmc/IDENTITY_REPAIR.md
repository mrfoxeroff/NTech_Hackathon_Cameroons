# Исправление раздвоения ID на двух камерах

Проверено 7 ноября 2026 года на новых синхронизированных наблюдениях из
`camera_new_1.mkv` и `camera_new_2.mkv`. Исходные видео и прежние результаты сохранены.

## Результат

Новое видео: `sync-check/cameras-synchronized-id-fixed.mp4` — 83,04 секунды,
1440×660, H.264, 1038 кадров. Это четыре контрольных эпизода, **не полная запись**.

| Эпизод | Предыдущий прогон | Новый прогон |
|---|---:|---:|
| Четыре человека | 14 треков | 4 трека |
| Два человека в тёмной одежде | 2 | 2 |
| Синяя куртка | 1 | 1 |
| Тёмная куртка | 2 | 1 |

Номера начинаются заново в каждом эпизоде. Сумма не является числом уникальных
людей за всю запись. Сокращение количества треков само по себе не доказывает
качество: дополнительно просмотрены ключевые кадры, переходы локальных ID
и сцены пересечения. Полной независимой покадровой разметки этих записей нет.

Все 1665 входных наблюдений сохранены. У 7 наблюдений первого эпизода ID
не подтверждён: три слишком коротких частичных обнаружения и четыре кадра
около смены личности в локальном треке. В видео это серый `ID ?`, в выгрузке
`global_id: null` с причиной. Они не объявляются новыми подтверждёнными людьми.
Это наблюдения, а не семь разных людей или семь уникальных видеокадров.

## Что вызывало проблему

1. Краткие ложные фрагменты конкурировали с длительными совпадениями по почти
   одинаковому баллу. Большая неоднозначная группа превышала ограничение
   точного перебора, поэтому сопоставление оставалось неразрешённым.
2. Несколько локальных ID обозначали одного человека одновременно.
3. После пересечения локальный ID камеры 2 переходил от человека в белом
   к человеку в чёрной футболке, затем к человеку в тёмной толстовке.
   Усреднённый ReID такого трека описывал сразу нескольких людей.
4. В последнем эпизоде Intel ReID не проходил порог между ракурсами.

## Изменения

* `associate.py`: дополнительное ранжирование по длительности подтверждённого
  совпадения. Используются занятые временные интервалы по 200 мс, а не сырое
  число кадров. Порог сходства внешности не снижен.
* `stabilize_tracklets.py`: объединение дублирующих локальных рамок требует
  совпадения времени, перекрытия рамок, близкого положения верхней части тела
  и сходной внешности. Проверяются все совместные кадры. Наблюдения сохраняются.
* `refine_cross_camera.py`: для двух камер строится вспомогательное соответствие
  верхних точек рамок по двум длительным взаимно лучшим ReID-совпадениям.
  В первом эпизоде использованы 214 пар для построения и 75 пар из отдельных
  секунд для проверки. Медианная ошибка проверки — 0,056 высоты рамки;
  97,3% проверочных пар укладываются в 0,35 высоты рамки.
* В кадрах с пересечениями выполняется совместное назначение соответствий:
  положение, внешний вид, продолжение движения и запрет назначить один ID
  разным одновременным локальным трекам. Прежний локальный ID не считается
  доказательством неизменной личности. Неуверенные границы остаются без ID.
* `enrich_osnet.py`: OSNet x0.25 MSMT17 извлекает дополнительные признаки из
  уже сохранённых кропов. Для ещё несвязанных однокамерных групп применяется
  резервное сопоставление с порогом 0,65 и минимум тремя признаками с каждой
  стороны. Оно не пересматривает установленные Intel-сопоставления.
* `render_synced.py`: отображает неподтверждённые наблюдения серым `ID ?`.

Геометрическое соответствие — **не калибровка пола и не координаты на плане**.
Оно приближённо связывает верхние части рамок людей похожего роста в двух
неподвижных ракурсах. При недостаточной проверке геометрия не включается.
При явном выходе человека или разрывах источника используется прежнее ядро
с ограничениями непрерывности. Геометрическое уточнение сейчас рассчитано на
две камеры. Для пяти камер нужен отдельный этап распространения согласованных
соответствий по графу камер и проверка на новых сценах.

## Проверка и артефакты

* 139 автоматических тестов проходят, включая 11 новых проверок: конкуренция
  кратких и длительных совпадений, дубли, пересечения, смена локального ID,
  недостаток геометрических опор, выход, отсутствие OSNet и резервное сопоставление.
* Прежний короткий пилот сохраняет два правильных ID без смешивания эталонных людей.
* Повторное уточнение даёт побайтово одинаковые назначения ID во всех эпизодах.
* Видео полностью прочитано декодером; проверены ключевые кадры.
* Назначения для видео: `sync-check/id-repair/verified/<эпизод>/assignments.jsonl`.
* Отчёт: `sync-check/id-repair/verified/report.json`.
* Проверки и хеши: `sync-check/id-repair/verified/checks.json`.
* Контрольные кадры: `sync-check/id-repair/verified/video-review.jpg`.
* Повторный прогон с хешами исходных и обогащённых наблюдений в манифестах:
  `sync-check/id-repair/reproducibility-check/`.

Нейросети не обучались. Разметка личностей не поступает в алгоритм.
Изменения проверены на данном наборе разработки; результаты не являются
оценкой точности на полной двадцатиминутной записи или новых камерах.
Синхронизация по экранным часам сохранена; физическая кадровая точность не подтверждена.

## Повторный запуск

Из корня рабочей папки, в новые выходные каталоги:

```powershell
& './mtmc/.venv/Scripts/python.exe' mtmc/refine_cross_camera.py `
  --demo mtmc/sync-check/tracked-demo/demo.json `
  --enriched mtmc/sync-check/id-repair/osnet `
  --config mtmc/camera_graph.stable.json `
  --output mtmc/sync-check/id-repair/next-run

& './mtmc/.venv/Scripts/python.exe' mtmc/render_synced.py `
  --alignment mtmc/sync-check/alignment.json `
  --demo mtmc/sync-check/id-repair/next-run/demo.json `
  --output mtmc/sync-check/cameras-id-next-run.mp4
```

Для новых локальных результатов сначала выполнить
`enrich_osnet.py <каталог-global-с-эпизодами> <новый-каталог-osnet>`.
Уточнение проверяет, что обогащённые строки полностью совпадают с исходными
наблюдениями, кроме добавленных OSNet-признаков.

`process_synced_demo.py` теперь по умолчанию запускает OSNet и уточнение после
локального этапа. `demo.local.json` сохраняет исходный результат, `demo.json`
указывает на уточнённый. Флаг `--baseline-only` оставляет прежний путь для
сравнения. Полный повтор детекции после изменения обвязки не запускался:
уточнение и рендер проверены на сохранённых новых наблюдениях.

```powershell
& './mtmc/.venv/Scripts/python.exe' -m pytest -c mtmc/pytest.ini -q
```
