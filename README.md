# Интерфейс межкамерного трекинга

Ветка `nikita` показывает два синхронизированных видео, контуры людей и их сквозные ID. Таймлайн управляет обоими плеерами. В списке можно выбрать любой трек, перейти к его началу и посмотреть интервалы по камерам. При включённом автоматическом выборе интерфейс подбирает камеры для выбранного ID.

## 1. Подготовка

Нужны Python 3.10+, FFmpeg и два исходных видео того же запуска, который обработала ветка `Dima`. Для интерфейса подготовь MP4 с кодеком H.264. Сохрани кадры, размеры и относительные метки времени исходного видео.

Команды выполняются из корня `nikita`.

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt

mkdir -p static/videos
ffmpeg -i /path/to/camera_new_1.mkv -map 0:v:0 -vf "setpts=PTS-STARTPTS" -fps_mode passthrough -c:v libx264 -pix_fmt yuv420p -movflags +faststart static/videos/cam_1.mp4
ffmpeg -i /path/to/camera_new_2.mkv -map 0:v:0 -vf "setpts=PTS-STARTPTS" -fps_mode passthrough -c:v libx264 -pix_fmt yuv420p -movflags +faststart static/videos/cam_2.mp4
```

В PowerShell окружение активируется командой `.\.venv\Scripts\Activate.ps1`. Используй свои пути к исходным видео. Не обрезай MP4 под эпизод, так как экспорт опирается на времена кадров полной записи.

## 2. Экспорт данных

Вход экспортёра — каталог **одного завершённого запуска** из ветки `Dima`. В нём должны быть `manifest.json`, `tracks.json`, `assignments.jsonl` и `observations.jsonl`. Порядок подготовки запуска описан в `Dima/README.md` и `Dima/mtmc/IDENTITY_REPAIR.md`.

Пример для эпизода `four_people` из `mtmc/process_synced_demo.py`. Его окно на общей шкале составляет 175–205 секунд.

```bash
python export_ui.py /path/to/demo/refined/four_people \
  --frame-log /path/to/demo/global/four_people/frames.jsonl \
  --window-sec 175 205 \
  --video cam_1=videos/cam_1.mp4 \
  --video cam_2=videos/cam_2.mp4
```

- Для базового запуска передай каталог `global/four_people`.
- Без `--frame-log` экспортёр ищет локальные `frames.jsonl` по манифесту запуска, затем проверяет `frames.jsonl` в переданном каталоге. Если пути из манифеста относятся к другому компьютеру, передай `--frame-log` явно. Опцию можно повторять для отдельных журналов камер одного запуска.
- Без `--window-sec` используется пересечение диапазонов обработанных кадров всех камер. Счётчик относится к окну экспорта. Чтобы показать результаты всей записи, экспортируй полный запуск, охватывающий нужное окно.
- При повторном экспорте останови сервер или обнови страницу после завершения экспорта.

### План офиса

Скопируй исходный план `office.jpg` из ветки `Dima` в `static/map.jpg`. Для плана нужны файлы `cam_1_calibration.json` и `cam_2_calibration.json` из `fedor`. Убедись, что калибровки соответствуют твоим камерам и тому же плану.

Добавь к команде экспорта параметры `--calibration-dir /path/to/fedor --plan map.jpg`. Для точек с сохранённым `footpoint_status` используй исходные локальные журналы через `--frame-log` по одному на камеру. Экспортёр показывает оценённые точки и старые точки без статуса как приблизительные. Точки вне плана и участки с длительным пропуском не отрисовываются.

## 3. Запуск

```bash
python app.py
```

Открой [http://127.0.0.1:8000](http://127.0.0.1:8000). Для проверки запусти видео, перемотай таймлайн, выбери ID и проверь карточку трека и контуры на двух камерах. Исходные видео, модели и сгенерированные файлы лежат отдельно от исходников.

## Файлы данных и время

| Файл | Содержимое |
| --- | --- |
| `static/tracks_metadata.json` | Окно эпизода, ссылки на видео, сквозные ID и интервалы по камерам. Времена карточек и карты отсчитываются от начала окна. |
| `static/clock_alignment.json` | Якоря для преобразования между временем плеера и общей шкалой. При наличии якорей используется кусочно-линейная интерполяция, затем применяется смещение из манифеста. |
| `static/overlays/<camera_id>.json` | Обработанные кадры, их время в видео, контуры и сквозные ID. |

Экспортёр соединяет наблюдения и назначения по `(camera_id, local_id, frame_index)`. Наблюдения без подтверждённого сквозного ID не попадают в список треков и оверлей. Интерфейс привязывает контур ко времени отображаемого кадра. Пустой обработанный кадр и кадр без разметки очищают оверлей. Синхронизация между камерами опирается на привязку экранных часов, точность зависит от качества якорей.
