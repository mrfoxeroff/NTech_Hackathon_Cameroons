# Сквозной трекинг людей

Отчёт команды **Cameroons** для хакатона NTech

## Задача и результат

Система обрабатывает пять записей офисных камер, объединяет наблюдения одного человека в сквозные треки и показывает его маршрут на плане. На записи длительностью **20 минут 4 секунды** система выделила **118 подтверждённых треков**. Из них 72 наблюдались на двух и более камерах, 6 — на всех пяти. [Данные готового сеанса](https://github.com/mrfoxeroff/NTech_Hackathon_Cameroons/blob/9c38781/outputs_all/session/session.json)

Каждый сквозной ID учитывается один раз. Если при возвращении человеку выдан новый ID, в журнале появляются две строки. Время начала и конца трека берётся из первого и последнего принятых наблюдений.

## Как работает система

1. **Общая шкала времени.** По экранным часам привязываем время каждого видеофайла к общей шкале. Это позволяет показывать один момент с разных камер.
2. **Силуэты и локальные ID.** YOLO11s-seg с весами `person-office-v2.pt` выделяет силуэты. ByteTrack связывает наблюдения в пределах одной камеры. Фильтры сцены убирают часть срабатываний на отражения, экраны и мебель.
3. **Геометрическая привязка.** На кадре каждой камеры вручную отметили опорные точки на плоскости пола и сопоставили их с теми же точками на плане здания. По этим парам OpenCV вычислил гомографию — матрицу, которая переводит пиксельные координаты кадра в координаты плана.

   В пяти файлах от `cam_1_calibration.json` до `cam_5_calibration.json` сохранили пары координат, матрицу и ошибки проекции для каждой камеры. На общий план переносится точка у ног человека. Если ноги закрыты, система может взять видимую опору с другого ракурса. При неопределённой позиции на маршруте остаётся разрыв. [Пример калибровки](https://github.com/mrfoxeroff/NTech_Hackathon_Cameroons/blob/9c38781/cam_1_calibration.json)
4. **Межкамерное сопоставление.** Intel ReID 0288 через OpenVINO извлекает признаки внешности. Алгоритм проверяет время и допустимую пару камер, затем сравнивает внешность, положение на плане и направление движения. При двух сопоставимых кандидатах фрагменты остаются раздельными.
5. **Подтверждение трека.** Для обычного трека с одной камеры нужны 1,75 с связной видимости и пять наблюдений с подходящим силуэтом. Для дальнего одиночного трека нужны 2,85 с и девять наблюдений. Так система отсеивает часть кратких ложных срабатываний. [Настройки и пороги](https://github.com/mrfoxeroff/NTech_Hackathon_Cameroons/blob/9c38781/configs/web-camera-graph.json)

## Вклад команды

Из готовых компонентов PyAV читает видео, YOLO выделяет силуэты, ByteTrack ведёт локальные треки, Intel ReID извлекает признаки внешности. Команда дообучила детектор и реализовала привязку часов, проекцию на план, межкамерное сопоставление, проверку конфликтов и правила восстановления ID. [Контракт данных](https://github.com/mrfoxeroff/NTech_Hackathon_Cameroons/blob/9c38781/docs/data_contract.md)

## Интерфейс

В двух окнах можно выбрать любые камеры и смотреть один момент по общей шкале времени. Рамки показывают сквозные ID. В журнале указаны начало, конец и список камер для каждого трека. Щелчок по ID переносит к началу трека и показывает его маршрут на плане. План можно приближать и перетаскивать. Маски силуэтов доступны в диагностическом превью локальной обработки. [Описание плеера и формата сеанса](https://github.com/mrfoxeroff/NTech_Hackathon_Cameroons/blob/9c38781/docs/web_demo.md)

## Три эпизода из готового сеанса

Таймкоды стоп-кадров указаны по шкале плеера. Паузы рассчитаны по границам принятых наблюдений в журнале.

| Что показать | Камера и таймкоды | Что произошло |
| --- | --- | --- |
| Возврат с тем же ID | Камера 4 · `00:27.6` и `01:19.4` | Человек возвращается к той же двери. Система сохраняет ID 4 после паузы 50,952 с. |
| Возврат с новым ID | Камера 5 · `01:30.6` и `04:56.3` | Человек в светлом жакете сначала получает ID 8, затем ID 31. Между треками прошло 3 мин 21 с. |
| Смена ID при перекрытии | Камера 5 · `05:33.1` и `05:34.2` | Другие люди перекрывают человека в белой футболке. После перекрытия он получает ID 47 вместо ID 40. |

## Когда трек заканчивается

Когда наблюдения пропадают во всех ракурсах, ID исчезает из списка активных, а текущая точка на плане пропадает. У настроенной двери система может восстановить прежний ID в течение 60 с после последнего наблюдения, если совпадают место появления и признаки внешности по нескольким наблюдениям.

По ТЗ подтверждённый выход из всех ракурсов закрывает трек. Правило для двери может объединить два отдельных эпизода. Перекрытие в толпе может разделить один проход, как в случае ID 40 и ID 47. Обе ошибки влияют на счётчик.

## Проверка эпизодов

Сверили три эпизода по кадрам плеера и журналу. Для возвратов проверили ID до и после паузы и вычислили её длину по границам наблюдений. В эпизоде с перекрытием проверили смену ID по кадрам камеры 5. Для оценки точности на всей записи нужна независимая разметка видео. ## Запуск и ведомость

Из корня репозитория установите зависимости и запустите плеер с готовым сеансом.

```powershell
python -m pip install -r requirements-player.txt
python app.py
```

Откройте [плеер в браузере](http://127.0.0.1:8000). В [ведомости треков](NTech_Cameroons_Tracks.csv) 118 строк с ID, временем начала и конца и списком камер. [Репозиторий и инструкция по запуску](https://github.com/mrfoxeroff/NTech_Hackathon_Cameroons)
