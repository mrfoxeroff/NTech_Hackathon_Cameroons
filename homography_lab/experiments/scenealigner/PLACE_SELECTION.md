# Автоматический выбор места: новая версия эксперимента

Новый модуль пока **отказывается от окончательной привязки камеры 2**: разные места получают близкие оценки.
Ни один результат этого опыта не подключён к рабочему трекингу.

## Что изменено

1. `analytic_place_prepare.py` объединяет сегментацию пяти кадров в общей системе изображения.
   Голосование подавляет временные перекрытия. Параметры объектива и вертикаль берутся как устойчивые оценки
   по этим пяти кадрам; точки плана не передаются.
2. `floor_ray_geometry.py` пересекает лучи камеры с плоскостью пола. Нейросетевая глубина не нужна.
   Высота камеры пока условно равна единице: её масштаб поглощается преобразованием в координаты схемы.
   Лучи выше горизонта, неинвертируемые и слишком далёкие пересечения исключаются.
3. К границам добавлены окна и дверные области. Изображение пола нельзя сопоставлять с планом по произвольным
   точкам мебели: схема описывает другую плоскость. Даже новая сегментация иногда принимает выставочные стенды за стены.
4. `analytic_place_search.py` получает предложения от прежнего нейросетевого поиска **для всех выбранных обучающих кадров**,
   а также строит геометрические гипотезы. Известная удачная калибровка и контрольные точки не используются.
5. Проверяется свободное пространство: от проекции камеры до наблюдаемого пола не должна проходить стена плана.
   Шаг проверки зависит от длины луча, чтобы не перескакивать через тонкие перегородки.
6. `door_landmarks.py` добавляет Grounding DINO Tiny с запросом `a door. an open doorway.`.
   Координаты детектор предлагает сам. Опора допускается только рядом с видимым полом; совпадения объединяются
   по пяти кадрам, достаточно трёх разных кадров. Предполагаемый проём в зеркале был обнаружен как объект,
   но исключён из опор из-за отсутствия видимого контакта с полом.
7. Для дверного режима поиск дополнительно перебирает поворот с шагом 15° и сопоставляет опору
   с автоматически найденными дверями схемы. Это гипотезы соответствий, а не подтверждённые пары.
   Опция `--door-size-prior` сравнивает ширину двери после проекции с шириной проёма на схеме:
   она штрафует уменьшение всей сцены до маленького участка стены. Размеры в метрах не задаются.
   Ширина по рамке детектора приблизительная; ширина на плане оценивается по дуге двери.
8. Близкие численные варианты одной привязки объединяются по проекциям проб пола.
   Если разные места имеют разницу оценок меньше 20%, возвращается `abstained`, а рабочая калибровка не экспортируется.
   Даже статус `candidate_requires_validation` не означает подтверждённую точность.

Никакие координаты конкретной двери, комнаты или положения камеры в код не записаны.
Пороговые значения — общие параметры алгоритма. `cam_2` в экспортируемом описании — идентификатор текущего пилота.

## Границы опыта

- Новая подготовка и поиск выполнены для **камеры 2**, не для всех пяти камер.
- Пять кадров подготовки: примерно 01:00, 03:15, 07:45, 10:10, 15:00.
- Пять дополнительных кадров: 02:00, 07:00, 11:00, 16:00, 19:00. Их маски/двери не участвуют в выборе места.
- Исходная запись длится около 20 минут. Новые моменты заданы до сегментации и оценки.
- Регистрация каждого дополнительного кадра проверена отдельно от привязки к плану.
- Контрольные JSON читает только `analytic_place_evaluate.py` и генератор иллюстраций после поиска.
- Контрольные JSON приблизительные; перенос их точек на другие кадры не создаёт новую независимую разметку.
- Многократное наблюдение одной неподвижной двери подтверждает её устойчивость, но не определяет номер комнаты.
- Новое обучение не проводилось. Grounding DINO запускается локально, загружены открытые веса около 689 MB,
   версия `a2bb814dd30d776dcf7e30523b00659f4f141c71`, SHA-256 файлов в `door-model.json`.
- Поиск геометрии и мест после подготовки не требует GPU. Подготовка использует SegFormer и оценки GeoCalib;
   дверной этап — Grounding DINO. Pi3 остаётся только источником ранее сохранённых предложений.

## Как повторить

Запускать из `D:\AI's_directory`. Для каждого нового запуска указывайте новый выходной каталог:
скрипты специально не перезаписывают результаты.

```powershell
$experimentDir = Join-Path (Get-Location) 'homography_lab/experiments/scenealigner'
$scenePython = Join-Path (Get-Location) 'homography_lab/.venv-scene/Scripts/python.exe'
$runDir = Join-Path $experimentDir 'runs/analytic-place-v1'
$temporalDir = Join-Path $experimentDir 'runs/camera-2-temporal'

# Повторный поиск по уже подготовленным нейросетью признакам; точки вручную не нужны.
& $scenePython "$experimentDir/analytic_place_search.py" `
  --features "$runDir/features" --inference "$temporalDir/inference" `
  --registration "$temporalDir/registration.json" `
  --plan-walls "$experimentDir/inputs/office-five-structural-v2/plan-walls.png" `
  --doors "$runDir/doors-size/doors.json" --door-size-prior `
  --plan-semantics "$experimentDir/inputs/office-five-structural-v2/semantics.json" `
  --output "$experimentDir/runs/place-repeat"

# Только после завершения поиска — оценка по контрольным точкам.
& $scenePython "$experimentDir/analytic_place_evaluate.py" `
  --search "$experimentDir/runs/place-repeat/search.json" --features "$runDir/features" `
  --registration "$runDir/validation-registration.json" `
  --reference "$experimentDir/reference/cam_2_calibration.json" `
  --plan-walls "$experimentDir/inputs/office-five-structural-v2/plan-walls.png" `
  --output "$experimentDir/runs/place-repeat/evaluation.json"
```

## Следующий вектор: калибровка через движение между камерами

**Начальный модуль уже реализован**: см. `MOTION_CALIBRATION.md` и `runs/motion-joint-final/RESULTS.md`.
Он совместно выбирает гипотезы по движению в перекрывающихся видах, не используя текущие глобальные ID как истину.
Переходы между неперекрывающимися камерами и надёжная автоматическая абсолютная привязка остаются дальнейшими этапами.
Прежняя совместная реконструкция 1–3 сама по себе эту задачу не решает.

### Последовательность

1. Сохранить несколько раздельных гипотез места для каждой камеры вместе с линзой, оценками и причинами отказа.
2. Из синхронизированных роликов отобрать только надёжные межкамерные пары наблюдений: близкое время,
   устойчивые признаки внешности на серии кадров, видимые стопы, отсутствие конкурирующего похожего человека.
   Нынешние глобальные ID нельзя использовать как истину: система уже путает их, это создаст замкнутую проверку.
3. Для перекрывающихся камер проверить, что при выбранных гипотезах стопы одного человека попадают в одну
   точку схемы. Для неперекрывающихся камер проверять порядок дверей, связность помещений и допустимое время перехода.
   Точки головы, столов, стен и произвольные совпадения изображений этому ограничению не подходят.
4. Совместно выбрать набор гипотез. Помимо собственной оценки камеры добавить устойчивую ошибку
   `||project_i(foot_i) - project_j(foot_j)||` по нескольким людям и моментам.
   Нелинейная коррекция линзы выполняется до гомографии. Координаты стоп и метки времени должны храниться в исходном разрешении.
5. После дискретного выбора уточнить положения камер общей оптимизацией, удерживая плоскость пола,
   вертикаль, границы и отсутствие проходов через стены. Не усреднять коэффициенты разных гомографий.
6. На непересекающихся по времени фрагментах проверить новые переходы и новых людей.
   Сравнить ошибку схемы, долю корректных автоматических инициализаций, долю отказов и число неверных ID.

Для абсолютного положения понадобится отличительный признак: связка нескольких дверей/окон, форма зоны
или читаемый номер помещения. Относительное совпадение траекторий само по себе не устраняет симметрию
повторяющихся комнат. OCR табличек может давать дополнительную гипотезу, но это отдельный будущий модуль.

Практичный порядок: сначала пара 1–3 с подтверждённым перекрытием; затем осторожно добавить камеру 2;
4–5 подключать по доказанным связям, не по соседству номеров. В компоненте без достаточных связей сохранять отказ.

Критерий прогресса: меньше **неверных принятых** привязок при сопоставимой доле успешных инициализаций.
Просто уменьшить ошибку одного удачно выбранного кадра или получить согласие десяти одинаковых кадров недостаточно.
