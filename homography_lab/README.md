# Лаборатория автоматической калибровки

Исследовательский модуль для привязки камер к плану и согласования их положений через движение людей.
Он отделён от рабочего плеера и трекера. Основная калибровка проекта не заменяется результатом опыта.

**Текущее состояние:** камеры 1–2 согласуются между собой лучше, но абсолютная привязка пока не подтверждена.
Отклонённые гипотезы не экспортируются как рабочие калибровки.

## Быстрая проверка после клонирования

Python 3.12, отдельное окружение лаборатории. Для примера не нужны видео, GPU, PyTorch или веса моделей.
Команды выполнять из корня репозитория:

```powershell
python -m venv homography_lab/.venv
./homography_lab/.venv/Scripts/python.exe -m pip install -r homography_lab/requirements-core.txt
./homography_lab/.venv/Scripts/python.exe homography_lab/demo.py --output homography_lab/runs/demo-01
```

На Linux используйте `homography_lab/.venv/bin/python`.
Для повторного расчёта выбирайте новый каталог `--output`.

Пример повторяет **геометрический этап по сохранённым автоматическим наблюдениям**.
Он не выдаёт кэш за новый запуск нейросетей. В `protocol.json` явно записаны
`video_inference_executed: false` и `neural_models_loaded: false`.

Результаты:

- `joint.json` — гипотезы, связанные компоненты и причины отказа;
- `accepted.json` — принятые калибровки; для текущего примера словарь пуст;
- `protocol.json` — режим и итог расчёта.

## Проверки

```powershell
cd homography_lab
./.venv/Scripts/python.exe -m pytest -c pytest.ini -q
```

Этот набор проверяет геометрию, сопоставление, переносимость путей, отсутствие пересечения временных выборок,
экспорт и запуск примера из постороннего каталога. Он не скачивает модели.
Результаты проверки перед публикацией: [VALIDATION.md](VALIDATION.md).
Исторические тесты нейросетевой реконструкции лежат в `experiments/scenealigner`; полный набор требует
дополнительных исследовательских зависимостей и не входит в минимальную установку.

## Полная обработка видео

Установите подходящую CPU/CUDA-сборку PyTorch, затем зависимости **в отдельное окружение лаборатории**:

```powershell
./homography_lab/.venv/Scripts/python.exe -m pip install -r homography_lab/requirements-motion.txt
```

Не устанавливайте этот набор поверх окружения рабочего трекера: для лаборатории закреплён OpenCV 4.13,
а основная ветка использует другие версии.

Внешние файлы не включены в Git:

| Данные | Путь по умолчанию |
|---|---|
| Исходные записи пилота | `data/video/camera_new_1.mkv` … `camera_new_3.mkv` |
| YOLO11n Pose | `homography_lab/experiments/scenealigner/cache/yolo11n-pose.pt` |
| OSNet MSMT17 | `mtmc/weights/osnet_x0_25_msmt17.pth` |
| Intel ReID | `mtmc/weights/person-reidentification-retail-0288.xml` и `.bin` |
| Локальный снимок SegFormer | `homography_lab/neural_weights/huggingface/` |

Происхождение моделей и контрольные суммы: [MODEL_ASSETS.md](MODEL_ASSETS.md).
План, маски, параметры объектива, шаблоны часов и автоматические предложения мест включены
в `experiments/scenealigner/assets/office`. Ручные `cam_*_calibration.json` основного проекта не входят во входы расчёта.

Сначала проверьте входы; каталог результатов при этом не создаётся:

```powershell
./homography_lab/.venv/Scripts/python.exe homography_lab/experiments/scenealigner/motion_run.py `
  --config homography_lab/configs/office-motion.example.json --check-inputs
```

Затем запустите:

```powershell
./homography_lab/.venv/Scripts/python.exe homography_lab/experiments/scenealigner/motion_run.py `
  --config homography_lab/configs/office-motion.example.json `
  --output homography_lab/runs/office-01
```

`--video-root` позволяет указать другую папку с записями, `--weights-root` — другую папку ReID-весов,
`--pose-weights` — файл позы, `--hf-cache` — локальный кэш SegFormer.
По умолчанию все стадии используют один Python; `--cpu-python` позволяет выделить отдельное окружение OpenVINO.
`--device auto` выбирает GPU при доступности, иначе CPU. Можно явно указать `--device cpu`.

Пути внутри JSON разрешаются относительно самого файла конфигурации, а не текущего каталога.
Пересекающиеся окна, повторяющиеся/небезопасные имена и несоответствие SHA-256 записей банку гипотез отклоняются.
Встроенный банк относится к исходным записям этого офиса; для другого объекта нужен новый автоматический банк.

## Результат и безопасное подключение

Потребители рабочего трекера должны читать **`accepted_calibrations`**, а не `calibrations`.
Поля `calibrations` (совместимость со старыми опытами) и `candidate_calibrations` содержат диагностические варианты,
в том числе отклонённые.

`motion_export.py` пишет отдельные файлы камер только при подтверждённом абсолютном месте,
готовности результата и принятых компонентах. Для текущего пилота папка `accepted` содержит только манифест
`no_accepted_calibrations`.

## Что уже проверено на записях

Обработано 1876 кадров камер 1–3. На восьми предложенных парах других эпизодов межкамерное расхождение
камер 1–2 снизилось с **176.8 до 4.7 пикселя схемы**. Это согласованность проекций, не подтверждение личности
и не измерение ошибки настоящих людей. Абсолютная привязка камеры 2 ухудшилась, поэтому результат отклонён.

Камера 3 не получила надёжной связи; 4–5 не обрабатывались в пилоте.
Переходы между неперекрывающимися камерами ещё не реализованы.
Официальная минута организаторов не изменяется этим исследовательским опытом.

Остальные файлы лаборатории сохраняют предыдущие эксперименты: ручной интерфейс,
поиск фрагментов плана, коррекцию линзы, SceneAligner и проверки на других кадрах.
Их исторические инструкции могут ссылаться на локальные архивы; для воспроизводимого старта используйте команды этой страницы.
