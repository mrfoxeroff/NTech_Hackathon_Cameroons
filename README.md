# Детекция и локальный трекинг людей

Модуль первой части проекта: предварительная обработка видео каждой камеры, сегментация людей и сопровождение с локальными ID. Результаты предназначены для межкамерного сопоставления, проекции на план и веб-интерфейса.

Конвейер: `видео → кадры и время → YOLO-сегментация → ByteTrack → наблюдения, маски, кропы и диагностика`. Камеры обрабатываются последовательно с независимым состоянием трекера. Обучение модели для первого запуска не требуется.

По умолчанию подключены дообученные веса `weights/person-office-v1.pt`; в текущем
checkout они уже подготовлены. Для нового клона передайте их отдельно либо используйте
`--config configs/cameras.pretrained.yaml` с официальными весами. Измерения и ограничения
описаны в [отчёте дообучения](docs/finetuning_report.md).

Текущий порог детекции — **0.50**. Дополнительно включены фильтры экранов камеры 3
и статичного игрового стола камеры 1: [правила и ограничения](docs/scene_filtering.md).

Добавлены фильтры зеркал камер 2–4 и стабилизация рамок при перекрытиях столами,
людьми и светильниками. Опора может быть прогнозируемой или неизвестной;
[новые поля и проверки](docs/occlusion_geometry.md). Актуальные примеры —
`outputs_occlusion_v3/`; `outputs_scene_v2/` сохранён, более старые результаты удалены.

## Установка в Windows / PowerShell

Нужен Python 3.12 или новее и актуальный драйвер NVIDIA для запуска на GPU. В рабочем окружении обнаружена RTX 5060 с **8 ГБ** видеопамяти. Размер модели, разрешение и скорость нужно подбирать на конкретных записях.

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -m local_tracking doctor
.\.venv\Scripts\python.exe -m local_tracking download-model --config configs/cameras.yaml
```

CUDA-сборка выше предназначена для GPU NVIDIA; при необходимости CPU установите PyTorch по [официальной инструкции](https://pytorch.org/get-started/locally/) и используйте `--device cpu`. Активация окружения не нужна: команды вызывают его Python напрямую.

Для воспроизведения проверенного окружения Windows x64 / Python 3.14 вместо двух команд установки пакетов используйте:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-lock.txt
.\.venv\Scripts\python.exe -m pip install -e . --no-deps
```

Lock-файл фиксирует версии и индекс CUDA 12.8; для другой ОС или версии Python используйте обычную установку выше.

Команда `download-model` явно загружает стандартные веса по пути `model` из конфигурации и требует доступа к сети. Уже существующий файл не перезаписывается. Команда `process` никогда не скачивает веса: при их отсутствии завершается с инструкцией загрузки. После подготовки окружения и весов обработка выполняется локально.

## Данные и конфигурация

Исходные видео ожидаются в `data/video/camera_1.mkv` … `camera_5.mkv`. Схемы в `data/image/` нужны следующим модулям; локальный трекинг не требует калибровки камер или знания FOV.

Основная конфигурация — [`configs/cameras.yaml`](configs/cameras.yaml). Все пути внутри YAML считаются относительно самого файла YAML. В частности, `../data/video/camera_1.mkv` ведёт в каталог `data` проекта.

| Настройка | Значение по умолчанию | Назначение |
|---|---|---|
| `model` | `../weights/person-office-v1.pt` | Дообученная на кадрах офиса YOLO11s-seg |
| `device` | `auto` | Автовыбор GPU/CPU; можно указать `cpu` или `0` |
| `imgsz` | `640` | Размер входа нейросети |
| `fp16` | `true` | Половинная точность на поддерживаемом GPU |
| `stride` | `1` | Обрабатывать каждый исходный кадр |
| `lost_track_sec` | `1.0` | Допустимый пропуск для локального сопровождения |
| `crop_interval_sec` | `0.5` | Интервал сохранения кропов одного трека |
| `selected_crops_per_track` | `5` | Число выбранных кропов в сводке |
| `save_masks` / `save_preview` | `true` | Сохранение масок и диагностического видео |

Порог `confidence` согласован с нижним порогом ByteTrack: слишком высокая фильтрация детектора лишает трекер слабых обнаружений для восстановления. `lost_track_sec` относится к одной камере и не задаёт завершение сквозного трека.

Для предоставленных видео общая шкала опирается на экранные часы камер (OSD): пользователь подтвердил их синхронность. За ноль принято `2026-10-08 17:38:39`; часовой пояс неизвестен. Медийные PTS отличаются от этих часов не только начальным смещением, но и скоростью хода, поэтому `clock_anchors` в конфигурации задают соответствия локального времени видео и общей шкалы. Между точками применяется линейная интерполяция, вне диапазона — экстраполяция; `time_offset_sec` добавляется как коррекция. Замеры приведены в [`docs/clock_alignment.json`](docs/clock_alignment.json). Это ручная привязка по отображаемым часам, без гарантии точности до кадра.

## Запуск

Проверить параметры всех записей:

```powershell
.\.venv\Scripts\python.exe -m local_tracking inspect --config configs/cameras.yaml --output outputs/video_info.json
```

Первый короткий запуск одной камеры:

```powershell
.\.venv\Scripts\python.exe -m local_tracking process --config configs/cameras.yaml --camera camera_1 --start 0 --end 10 --output-root outputs_smoke
.\.venv\Scripts\python.exe -m local_tracking validate outputs_smoke/office_01/camera_1
```

Обработать все камеры полностью:

```powershell
.\.venv\Scripts\python.exe -m local_tracking process --config configs/cameras.yaml
```

Выбрать несколько камер, ограничить число обработанных кадров или изменить частоту:

```powershell
.\.venv\Scripts\python.exe -m local_tracking process --config configs/cameras.yaml --camera camera_1 --camera camera_2 --max-frames 100 --stride 2 --output-root outputs_check --no-preview
```

`--start` и `--end` задаются в секундах внутри каждого исходного видео; конец интервала не включается. `--max-frames` ограничивает число обработанных кадров на камеру. При `stride > 1` сохраняются исходные номера кадров и времена. Такой режим нужно отдельно проверить на быстрых переходах и пересечениях людей.

Каталог камеры при повторном запуске не перезаписывается. Для нового эксперимента укажите другой `--output-root`. Это предотвращает смешивание результатов разных настроек.

## Выходные файлы

```text
outputs/office_01/camera_1/
  manifest.json       # источник, конфигурация, версии, статус запуска
  frames.jsonl        # одна запись на обработанный кадр, включая пустые
  local_tracks.json   # сводки локальных треков и интервалы видимости
  metrics.json        # измерения выполненной обработки
  preview.mp4         # диагностическое видео, если включено
  masks/              # маски людей в координатах ROI
  crops/              # вырезки из чистых исходных кадров
```

Полный контракт полей и правила интеграции находятся в [`docs/data_contract.md`](docs/data_contract.md).

`preview.mp4` содержит локальные ID, силуэты и точки опоры. Это диагностический ролик с постоянной частотой кадров по медийному времени, без коррекции скорости по OSD. При большом разрыве исходных кадров он показывает чёрный экран `NO SOURCE FRAMES`, не удерживая прежние рамки. Для синхронизации интерфейса используйте исходное видео и общую шкалу `timestamp_sec` из JSONL, а не номер кадра превью или необработанные PTS.

В `manifest.json` различаются выполняемый, завершённый и аварийно завершённый запуски. Частичные файлы после ошибки могут быть полезны для диагностики, но не считаются полным результатом. Всегда проверяйте статус.

## Проверки и ограничения

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m local_tracking validate outputs/office_01/camera_1
```

`validate` проверяет завершённость запуска, структуру данных и связанные артефакты. Проверяйте также реальные фрагменты с остановкой человека, перекрытием мебелью, пересечением людей, выходом из кадра и повторным появлением. Контролируйте пропуски, обмены ID, разрывы и фактическую скорость обработки. У nano-модели на этих сценах возможны ложные обнаружения стульев и изображений на экранах; безошибочные ID и полнота детекции не гарантируются.

Сохраняются фактические обнаружения; предсказание положения трекером при отсутствии детекции не выдаётся за наблюдение. Не получившие подтверждённый локальный ID обнаружения также экспортируются с `local_track_id: null`.

Точка опоры — нижний центр рамки, приблизительная оценка для последующей проекции. Закрытые ноги и обрезание изображения делают её ненадёжной. Координаты на плане и глобальные ID назначают следующие модули. Число локальных треков нельзя использовать как общее число сквозных треков.

Видео, схемы, веса, результаты и локальное окружение исключены из Git через `.gitignore`. Исходные данные нужно передавать отдельно.

Официальные материалы: [Ultralytics Tracking](https://docs.ultralytics.com/modes/track/), [Segmentation](https://docs.ultralytics.com/tasks/segment/), [PyAV: время кадров](https://pyav.org/docs/stable/api/time.html). Условия использования готовых моделей и библиотек определяются их лицензиями.
