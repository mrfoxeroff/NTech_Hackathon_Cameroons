# Контракт наблюдений локального трекинга

Данные относятся к одной записи и одной камере. Они предназначены для межкамерного алгоритма, модуля геометрии и интерфейса. Сводки этого модуля описывают локальные треки; сквозные треки и итоговый счётчик формируются отдельно.

## Система координат и времени

Все координаты рамок, контуров и точек опоры выражены в пикселях **исходного кадра**. Начало находится в левом верхнем углу, X растёт вправо, Y — вниз. Рамка записывается как `[x1, y1, x2, y2]`. Уменьшение входа нейросети не меняет систему координат выходных данных.

`frame_index` — индекс исходного декодированного кадра, начиная с нуля. При `stride=3` возможны индексы `0, 3, 6, …`; перенумерации обработанных кадров нет.

`media_time_sec` — исходный PTS кадра, умноженный на `time_base`, без обнуления; при недоступном PTS поле равно `null`. `video_time_sec` — медийное время относительно первого декодированного кадра видео. При недоступных метках используется номер кадра и FPS. `timestamp_source` обозначает способ получения медийного времени (`pts` или `index_fps`), а не точность синхронизации часов.

`timestamp_sec` — общая шкала записи, по которой следует сопоставлять камеры. При отсутствии `clock_anchors`:

```text
timestamp_sec = video_time_sec + time_offset_sec
```

При наличии `clock_anchors` каждый якорь задаёт пару `{video_time_sec, timestamp_sec}`. Между соседними якорями выполняется линейная интерполяция; вне их диапазона — линейная экстраполяция по крайнему отрезку. После преобразования добавляется `time_offset_sec`. На обеих осях значения якорей строго возрастают; требуется минимум два якоря.

В предоставленных видео выявлено различие хода медийного времени и экранных часов камер (OSD); одной константы смещения недостаточно. По подтверждению пользователя OSD синхронны. Ноль общей шкалы принят за `2026-10-08 17:38:39` экранного времени; часовой пояс неизвестен, поэтому это не Unix timestamp и не UTC. Исходные замеры привязки сохранены в [`clock_alignment.json`](clock_alignment.json). Точность привязки зависит от ручного чтения OSD и не подтверждена покадровой эталонной разметкой.

Выбор `--start` не обнуляет временную шкалу данных. Границы `--start`/`--end` относятся к `video_time_sec`, а не к скорректированному `timestamp_sec`. Для поиска исходного кадра по общей шкале используйте сохранённые пары времён; нельзя считать, что `timestamp_sec` равен PTS или времени видеоплеера.

## manifest.json

Метаданные источника находятся в `source`, конфигурация — в `configuration`, версии и устройство — в `runtime`. `source.first_frame_time_sec` хранит медийное время первого кадра. SHA-256 источника и весов записываются в `source_sha256` и `weights_sha256`. `selection` содержит выбранный интервал и лимит кадров; `frame_stride` — частоту выборки. `timestamp_origin` описывает обнуление локального медийного времени; `clock_anchors` и `time_offset_sec` задают последующее преобразование в общую шкалу.

`status` принимает значения `running`, `complete` или `failed`. Используйте его для проверки полноты результатов. При ошибке в `error` сохраняются тип и сообщение; файлы камеры могут содержать только обработанную часть. `complete` означает завершение выбранного интервала или лимита, а не обязательно полного исходного видео.

Составной идентификатор трека:

```text
(recording_id, camera_id, local_track_id)
```

Одинаковые номера локальных ID на разных камерах не означают одного человека. Результаты разных запусков нельзя объединять только по локальному номеру.

## frames.jsonl

Одна строка JSON на каждый обработанный кадр. Кадр без людей обязательно присутствует с `observations: []`. Отсутствующая строка не должна интерпретироваться как отсутствие людей: кадр мог быть пропущен по `stride`, находиться вне выбранного интервала или не быть обработан из-за ошибки.

| Поле кадра | Значение |
|---|---|
| `recording_id` | Идентификатор набора синхронных записей |
| `camera_id` | Идентификатор камеры |
| `frame_index` | Исходный индекс кадра |
| `media_time_sec` | Исходное медийное время PTS × time_base или `null` |
| `video_time_sec` | Медийное время относительно первого кадра |
| `timestamp_sec` | Общая шкала после коррекции по якорям и смещению |
| `timestamp_source` | Источник медийной временной метки |
| `source_gap_before_sec` | Большой разрыв до предыдущего обработанного кадра; иначе `0` |
| `frame_width`, `frame_height` | Размер исходного изображения |
| `observations` | Массив наблюдений людей |

| Поле наблюдения | Значение |
|---|---|
| `observation_id` | Уникальный ключ наблюдения в рамках результата |
| `local_track_id` | Целочисленный ID или `null`, если трек ещё не подтверждён |
| `bbox_xyxy` | Рамка фактического обнаружения, а не предсказание Калмана |
| `detection_confidence` | Уверенность детектора; не вероятность правильности идентичности |
| `mask_ref` | Относительный путь к PNG-маске ROI или `null` |
| `mask_origin_px` | Начало ROI на исходном кадре `[x, y]` |
| `mask_size` | Размер PNG-маски `[width, height]` |
| `silhouette_polygons` | Массив контуров в пикселях исходного кадра |
| `footpoint_px` | Приблизительная точка опоры `[x, y]` |
| `footpoint_method` | Метод оценки точки опоры |
| `touches_frame_bottom` | Признак касания рамкой нижней границы изображения |
| `border_flags` | Признаки касания границ изображения |
| `crop_ref` | Относительный путь к сохранённому кропу или `null` |
| `crop_quality` | Диагностические признаки качества сохранённого кропа или `null` |

Относительные ссылки разрешаются от каталога камеры, содержащего `manifest.json`.

`source_gap_before_sec` содержит разницу медийных времён соседних обработанных кадров, если она превышает `max(0.5, 3 × stride / fps)` секунд. Первый кадр имеет `0`. Это сигнал отсутствия кадров на участке источника, который нельзя интерпретировать как подтверждённое отсутствие людей.

Сведения о масках относятся к тому же обнаружению, что и рамка. PNG хранит значения `0` для фона и `255` для человека. Для восстановления маски на полном кадре вставьте PNG в изображение нулей, начиная с `mask_origin_px`. Контуры предназначены для отображения; они не обязаны сохранять все детали и отверстия бинарной маски.

`footpoint_method = bbox_bottom_center` означает:

```text
footpoint_px = [(x1 + x2) / 2, y2]
```

Эта оценка не гарантирует видимости стоп. `touches_frame_bottom = false` также не гарантирует пригодности точки: ноги могут быть закрыты мебелью. Модуль геометрии должен учитывать границы откалиброванной области и качество наблюдения.

Кроп берётся из чистого исходного изображения до нанесения рамок, текста и масок. Он сохраняется периодически для локального трека; отсутствие `crop_ref` не означает отсутствие человека. `crop_quality` содержит ширину, высоту, дисперсию лапласиана (`laplacian_variance`), признак обрезания (`truncated`) и эвристическую оценку ранжирования (`selection_score`). Эта оценка не является вероятностью пригодности кропа или совпадения личности. Для пиксельного API учитывайте, что OpenCV использует порядок BGR, а декодер JPEG потребителя может возвращать RGB.

Наблюдения с `local_track_id = null` являются настоящими обнаружениями, но пока не имеют подтверждённой связи во времени. Их нельзя объединять в общий «нулевой трек».

## Обработка перекрытий

В новых результатах для отображения используйте `bbox_stabilized_xyxy`, а не
исходный `bbox_xyxy`. Поле `footpoint_px` теперь может быть `null`; проверяйте
`footpoint_status` (`observed` / `estimated` / `unknown`). Прогноз не является
подтверждённой координатой на полу. Старое измерение доступно в `raw_footpoint_px`.
Подробности: [геометрия перекрытий](occlusion_geometry.md).

## local_tracks.json

Файл содержит `schema_version`, `recording_id`, `camera_id` и массив `tracks`. Сводки в массиве включают:

- локальный ID;
- `first_seen_sec` и `last_seen_sec` — первое и последнее фактическое наблюдение;
- `visibility_intervals` — интервалы наблюдаемости, сохраняющие пропуски;
- `observation_count` — число наблюдений;
- `selected_crops` — ссылки на выбранные изображения с оценками качества.

Каждый интервал имеет поля `start_sec` и `end_sec`; это времена первого и последнего наблюдения в серии последовательных обработанных кадров. Пропущенный по настройке `stride` исходный кадр сам по себе не разделяет интервал. Отсутствие обнаружения на обработанном кадре разделяет интервалы. Интервал от первого до последнего наблюдения не означает непрерывную видимость между сохранёнными отсчётами. Для точного наложения используйте строки `frames.jsonl`.

Элемент `selected_crops` содержит `crop_ref`, `observation_id`, `timestamp_sec` и `quality`. Число элементов ограничено `selected_crops_per_track`; отбор выполняется по `selection_score` среди периодически сохранённых кропов. Наблюдения без локального ID не образуют сводного трека.

Окончание локального фрагмента не означает окончания сквозного трека: человек может продолжать наблюдаться другой камерой. Решение о завершении сквозного трека принимает межкамерный модуль.

## metrics.json и preview.mp4

`metrics.json` содержит измерения конкретного запуска, включая `source_gap_count` — число отмеченных разрывов источника. Сравнивайте скорость только вместе с моделью, устройством, размером входа, частотой обработки и включёнными артефактами.

`preview.mp4` служит визуальной диагностикой. Это видео с постоянной частотой по локальному медийному времени относительно первого выбранного кадра; коррекция скорости по OSD в его временную ось не вносится. При большом разрыве исходных кадров выводится чёрный экран `NO SOURCE FRAMES`, а не старое положение человека. Для синхронизации нескольких камер, поиска кадра по времени и построения API используйте исходные видео вместе с `video_time_sec` и `timestamp_sec` из наблюдений.

Команда `python -m local_tracking validate <camera_output_dir>` проверяет завершённость и согласованность сохранённого результата. Она не оценивает правильность идентификации людей или точность OSD-привязки.
