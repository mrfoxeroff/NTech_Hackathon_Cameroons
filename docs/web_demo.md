# Сеанс плеера и HTTP API

Готовый сеанс пяти камер входит в репозиторий и лежит в `outputs_all/session`. После клонирования установите зависимости плеера и запустите сервер из корня проекта:

```powershell
python -m pip install -r requirements-player.txt
python app.py
```

Откройте `http://127.0.0.1:8000`. Список исходных файлов для повторной обработки приведён в [README](../README.md).

## Подготовка сеанса

`tools.run_web_demo` проверяет контрольные суммы исходных видео и привязывает их к общей шкале экранных часов. Привязка относится к конкретным записям. При замене записей или изменении положения камер нужно обновить привязку часов или геометрию соответственно.

- `--cameras 1 2` выбирает камеры. По умолчанию используются все пять.
- `--start` и `--end` задают границы обработки в секундах общей шкалы.
- `--stride 3` по умолчанию запускает детектор на каждом третьем кадре. `--stride 1` обрабатывает каждый кадр. Частота видео в плеере сохраняется.

В каталоге результата `local/` содержит наблюдения каждой камеры, `global/` — назначения сквозных ID, `session/` — готовые файлы плеера. Для просмотра достаточно перенести только `session/`.

Если уже есть `global/` и исходные файлы, сохранённые в его манифесте, можно повторить экспорт без запуска детектора.

```powershell
.\.venv\Scripts\python.exe -m tools.export_web_session outputs_new/global outputs_reexport/session
```

## Файлы плеера

```text
session/
  session.json            камеры, шкала времени, журнал треков
  world_state.json        наблюдения и координаты сквозных ID в общей шкале
  map.png                 план офиса
  camera_N.mp4            видео камеры
  camera_N_overlay.json   рамки и ID по времени видео
```

Сервер читает каталог из `NTECH_SESSION_DIR`. По умолчанию он ищет `outputs_all/session`, затем `outputs_full/session`. MP4 поддерживает HTTP Range, поэтому плеер может переходить к нужному времени без загрузки всего видео.

| Запрос | Что возвращает |
| --- | --- |
| `GET /api/session` | Метаданные сеанса версии `1.0` |
| `GET /api/state?t=26.20` | ID, наблюдаемые в 120-миллисекундном окне, их позиции и исходные кадры |
| `GET /media/map.png` | План офиса |
| `GET /media/camera_1.mp4` | Видео камеры |
| `GET /media/camera_1_overlay.json` | Рамки и ID камеры |
| `GET /docs` | Интерактивная документация FastAPI |

Интервалы видимости и точки на плане отсчитываются от `timeline_origin` в секундах. `clock_anchors` задают перевод между общей шкалой и временем MP4. Подпись кадра содержит время MP4 и массив рамок вида `[global_id, x1, y1, x2, y2]` в пикселях исходного видео.

`tracks_summary` индексируется сквозным ID. `camera_segments` хранит интервалы видимости, `map_path` — координаты в пикселях плана от его верхнего левого угла. Для `/api/state` позиция может быть `null`, если доступные проекции противоречат друг другу. Во время отсутствия человека его ID остаётся в журнале, а текущая позиция отсутствует.

Карта камер задаётся в [configs/web-camera-graph.json](../configs/web-camera-graph.json). Проверки синхронизации, дальних ракурсов и возвратов через дверь описаны в [отчёте по трекингу](tracking_audit.md).
