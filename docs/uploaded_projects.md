# Обработка нового помещения

Форма `/new` принимает один план в PNG/JPEG и от 1 до 32 видео. Каждый файл задаёт одну камеру. Поддерживаются MKV, MP4, MOV, AVI и WebM. Сервер запускается локально, хранит загруженные данные и обрабатывает один проект за раз. Запуск и веса описаны в [README](../README.md).

Во время детекции форма показывает устройство, номер камеры, количество обработанных кадров и позицию в записи. Для обработки на NVIDIA установите сборку PyTorch с CUDA до запуска сервера. В Windows проверена комбинация из `requirements-lock.txt`:

```powershell
.\.venv\Scripts\python.exe -m pip install --index-url https://download.pytorch.org/whl/cu128 torch==2.11.0+cu128 torchvision==0.26.0+cu128
.\.venv\Scripts\python.exe -c "import torch; print(torch.version.cuda, torch.cuda.is_available())"
```

При `None False` детекция будет выполняться на CPU. Замена сборки требует перезапуска сервера и нового прогона.

## Синхронизация

Записи должны показывать дату и время на синхронизированных часах камер. В стандартном режиме система ищет часы в верхних углах. Если часы расположены иначе, в форме можно задать одну область в относительных координатах, общую для всех загруженных записей. Для Tesseract нужен языковой пакет `eng`. При плохом распознавании проект выдаёт ошибку. Сдвиг по моменту начала файлов автоматически не применяется.

Для файлов офиса проверенные привязки времени выбираются по SHA-256. Для остальных используются прочитанные Tesseract смены секунд, порядок кадров и метки PyAV. Это выравнивание по отображаемым часам с интерполяцией долей секунды. Переменный кадровый темп, длинные монтажные разрывы, обрезанные часы и рассинхронизированные часы требуют отдельной проверки.

## Привязка камер к плану

Для исходного офиса загрузите `data/image/office.jpg` и нужные записи из `data/video`. Форма выбирает сохранённые калибровки по SHA-256 плана и каждого видео, независимо от имени файла и порядка загрузки. Метки для этого сценария не нужны. Межкамерное сопоставление учитывает проверенные пары офисных камер и пары, подтверждённые по движению.

Для другого помещения нужна привязка хотя бы одной камеры к плану. Доступный вариант с метками:

1. Для абсолютной опоры разместите на полу как минимум три разные метки `DICT_4X4_50`, широко разнесённые по полю зрения хотя бы одной неподвижной камеры. Нанесите те же метки на план в масштабе плана, с теми же центрами, размерами и ориентацией. Каждая метка проверяется матрицей, рассчитанной по остальным.
2. Используется принцип лаборатории Dima. Синхронные опорные точки связываются взаимным совпадением признаков внешности. Голоса группируются по паре треков и секунде. Для камеры без меток преобразование можно перенести с одной абсолютной опоры, если совпадения на отдельных временных блоках подтверждают перенос. Нужны движение по площади пола и наблюдения нескольких пар треков. Проекция ограничена областью проверенных точек. Непроверенные гипотезы не применяются.
3. Сквозное сопоставление включается для пар камер, где совпадения внешности и точек на плане поддерживаются в нескольких секундах. При отсутствии абсолютной опоры или достаточной общей видимости в плеере остаются синхронное видео и треки без межкамерной склейки для этих камер. На произвольном немаркированном плане лабораторный пилот пока не подтвердил абсолютное место даже для камер 1–2.

Рабочий пайплайн использует наблюдаемые опорные точки сегментации и Intel ReID. Исследовательский [конвейер лаборатории](../homography_lab/README.md) отдельно испытывает суставы стоп, OSNet, модель объектива и совместный выбор мест. Его подтверждённый `joint.json` можно подать в CLI. Импорт проверяет `accepted_calibrations`, флаги допуска, размеры, `plan_sha256` и словарь `source_sha256` по ID камеры. Диагностические `candidate_calibrations` игнорируются.

```powershell
.\.venv\Scripts\python.exe -m tools.run_uploaded_project --plan path/to/plan.png --video path/to/one.mkv --video path/to/two.mkv --output outputs_new_room
```

Сеанс появляется в `session/`, а в `localization.json` перечислены привязки и пары камер. По ссылке из формы этот же сеанс открывается в обычном плеере с выбором времени и масштабированием плана.

## Сохранение ID

Память хранится до 60 секунд с последнего появления на любой камере. При повторном появлении на том же ракурсе с близкой позицией и несколькими совпавшими признаками внешности старый ID может восстановиться даже без привязки к плану. При смене камеры дополнительно нужна проверенная общая зона наблюдения и близость на плане. Сопоставимые кандидаты остаются раздельными. В период отсутствия точка человека на карте не появляется.
