# Интеграция ветки misha

Источник: [NTech_Hackathon_Cameroons, ветка misha](https://github.com/mrfoxeroff/NTech_Hackathon_Cameroons/tree/misha).
Проверенный удалённый коммит: `00853f1242037ed4833eab3dd98cab8604e2d84a`.
Исходный checkout `NTech_Hackathon_Cameroons` остался на `main`, без изменений и публикаций.

Снимок исходников и тестов хранится в `integrations/misha-00853f1/`.
Происхождение и контрольные суммы исходных и адаптированных модулей — в
`integrations/misha-provenance.json`. Пакет `local_tracking/` взят из этой ветки.
Адаптированы два файла: `pipeline.py` для Python 3.10 и загрузки весов из пути
с апострофом, `__init__.py` для хранения настроек Ultralytics внутри проекта.

## Что перенесено и как используется

| Решение ветки | Интеграция |
|---|---|
| PyAV с исходными индексами и временными метками | Новый локальный этап сохраняет `frame_index`, исходное медийное время и общую шкалу отдельно; выбор интервала не перенумеровывает кадры |
| Кусочная привязка часов | Поддерживается в YAML как `clock_anchors`; её результат передаётся в `timestamp_ms`, исходный PTS сохраняется отдельно |
| Независимый ByteTrack каждой камеры | Трекинг выдаёт только обнаруженные объекты; предсказания без детекции не становятся наблюдениями |
| Полный журнал кадров | Кадры без людей остаются в `frames.jsonl`, пропуск обработки не подменяется пустым кадром |
| Маски ROI и чистые кропы | Сохраняются ссылки, исходные координаты, все полигоны и признаки обрезания кадром |
| Оценка качества кропов | Наш адаптер вычисляет ReID на периодических кропах и уменьшает вклад размытых, маленьких и обрезанных изображений |
| Явные разрывы источника | Разрыв создаёт новый `source_segment`; локальное объединение через него запрещено, интервалы видимости остаются разделёнными |
| Статусы и валидатор результатов | Незавершённые/повреждённые результаты, разные записи и повторные запуски одной камеры отклоняются |

Межкамерная логика остаётся собственной: `associate.py`. Новый адаптер
`import_local_tracking.py` соединяет готовый локальный результат с Intel 0288
и глобальными ID. Предыдущий `extract_observations.py` остаётся доступным для
воспроизводимости прежних экспериментов.

## Важные правила адаптера

- В одном импорте допускается одна запись (`recording_id`), одна общая временная
  система (`timeline_origin`) и один запуск на камеру. Нельзя смешивать локальные
  ID разных запусков одной камеры.
- `local_track_id: null` сохраняется отдельно в `unassigned.jsonl`. Это реальное
  обнаружение без подтверждённого локального ID, а не общий «нулевой человек».
- Отсутствие или плохое качество кропа не удаляет наблюдение. У него просто нет
  новых признаков внешности.
- Для ReID используются все подходящие периодически сохранённые кропы, а не
  только пять лучших за весь трек: иначе теряются признаки около границ фрагментов.
- `appearance_weight` — эвристический вес в диапазоне 0–1, не вероятность
  идентичности. Старые наблюдения без этого поля имеют вес 1 и дают прежний результат.
- `source_segment` меняется даже тогда, когда первый кадр после пропуска пустой.
  Следующее обнаружение наследует новый сегмент. Если другая камера непрерывно
  наблюдала человека, межкамерная связь может сохранить глобальный ID.
- Пропуск видеозаписи не выставляет `confirmed_global_exit`. Координаты нижнего
  центра рамки не превращаются автоматически в координаты на плане.
- При сбое импорта `manifest.json` получает статус `failed`. Команда
  `associate.py` отклоняет такой файл наблюдений. Выходные каталоги нового
  локального этапа и адаптера не перезаписываются.
- Маски и кропы остаются в каталогах локального этапа; `artifact_root` указывает
  на них. Для переноса результата на другую машину нужно перенести и эти каталоги
  и заново выполнить импорт, чтобы обновить пути.

## Запуск

Дополнительные зависимости уже установлены в `mtmc/.venv`:
`PyYAML==6.0.3`, `pytest==8.4.2`. Нейросетевые библиотеки не переустанавливались.
Команды выполняются из корня рабочей папки:

```powershell
# Локальный этап двух камер, короткий интервал для проверки.
& './mtmc/.venv/Scripts/python.exe' mtmc/local_stage.py process `
  --config mtmc/local_stage.example.yaml --start 174 --end 180

# Проверка результата конкретной камеры.
& './mtmc/.venv/Scripts/python.exe' mtmc/local_stage.py validate `
  mtmc/integration-runs/local/new_pair/cam_1

# ReID + собственный межкамерный алгоритм.
& './mtmc/.venv/Scripts/python.exe' mtmc/import_local_tracking.py `
  --input mtmc/integration-runs/local/new_pair/cam_1 `
  --input mtmc/integration-runs/local/new_pair/cam_2 `
  --config mtmc/camera_graph.improved.json `
  --output mtmc/integration-runs/global --associate

# Все исходные и интеграционные тесты.
& './mtmc/.venv/Scripts/python.exe' -m pytest -c mtmc/pytest.ini -q
```

Если каталог уже существует, задайте новый `--output-root` локальному этапу
и новый `--output` адаптеру. В YAML можно добавить остальные камеры; для
межкамерного сопоставления потребуется также их граф пересечений/переходов.

Выход адаптера:

- `observations.jsonl` — подтверждённые локальные наблюдения с ReID и исходными ключами;
- `frames.jsonl` — временная шкала обработанных кадров, включая пустые, и ссылки на наблюдения;
- `unassigned.jsonl` — обнаружения без локального ID;
- `manifest.json` — источники, контрольные суммы, настройки, счётчики и статус;
- при `--associate`: `assignments.jsonl`, `tracks.json`, `tracks.csv`.

## Проверка на наших данных

1. **122 автоматических теста:** 79 из ветки, 20 прежних тестов межкамерного
   алгоритма и 23 интеграционных сценария. Проверяются шкалы времени, оригинальные
   индексы, маски, пустые кадры, незавершённые запуски, качество кропов,
   пропуски источника и загрузка весов из директории с апострофом.
2. **Обратная совместимость:** назначения ID на четырёх прежних размеченных
   эпизодах совпали с предыдущей версией побайтно: 5, 2, 1, 2 трека,
   всего 10 при эталоне 8. Старый короткий пилот сохранил два правильных ID.
   Отчёты: `integration-runs/regression/`.
3. **Реальный полный путь данных:** два интервала 174–180 секунд, по 76 кадров
   с каждой камеры. После наших исключающих областей в межкамерный модуль
   передано 321 подтверждённое наблюдение с 68 эмбеддингами; ещё 226
   обнаружений без ID сохранены отдельно. Получено 4 глобальных трека.
   Это проверка работоспособности, а не эталонный подсчёт людей: эти новые
   детекции полностью не размечены, остаются ложные срабатывания.
   Результат: `integration-runs/combined/`.
4. **Реальный пропуск записи:** камера 1, интервал 223–237 секунд, 50 кадров.
   Зафиксирован разрыв PTS около 10,087 с. В диагностическом видео внутри
   пропуска показан `NO SOURCE FRAMES`; старые рамки не удерживаются.
   Результаты: `integration-runs/gap/` и `integration-runs/gap-combined/`.
5. Проверка зависимостей `pip check` проходит.

## Что не переносилось автоматически

Числовые `clock_anchors` ветки измерены для её `camera_1...camera_5`, а у нас
проверены `camera_new_1` и `camera_new_2`. Их полное соответствие не установлено,
поэтому эти значения хранятся только в исходном снимке. Возможность кусочной
коррекции перенесена, но синхронизация наших записей ещё требует собственных
проверенных опор. Пример YAML явно помечен `local_media_unverified` и использует
старое смещение +0,9 с только для совместимости короткого прогона.

Вместо весов YOLO11s из ветки оставлены уже имеющиеся YOLO11n-seg. Увеличение
модели и заявления о GPU-скорости ветки на наше окружение не переносились.
Веткой не реализованы ReID, геометрия плана и межкамерные глобальные ID;
эти компоненты нельзя считать полученными вместе с локальным трекером.

Результат интеграции — более проверяемый вход и корректное представление
неполных данных. Рост точности от нового локального этапа и весов качества
потребует отдельного сравнения на независимой разметке после исправления часов.
