# Демо камер 1–2 и HTTP API

Подготовка сеанса запускается из корня репозитория в Windows PowerShell.
Используйте окружение проекта с PyTorch и CUDA, если доступна GPU.

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[demo,dev]"
.\.venv\Scripts\python.exe -m tools.run_web_demo
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000
```

Откройте `http://127.0.0.1:8000`. Если готовый `outputs_full/session` уже есть,
достаточно запустить сервер. Для другого каталога задайте перед запуском
`$env:NTECH_SESSION_DIR = 'outputs_web_verified/session'`.

Для подготовки нужны исходные `data/video/camera_1.mkv` и
`data/video/camera_2.mkv`, фон `data/samples/camera_1.jpg`,
`weights/person-office-v2.pt` и пара `person-reidentification-retail-0288.xml` /
`.bin` в `mtmc/weights`. Видео, фон и веса передаются отдельно от Git.
Контрольные суммы и источник модели ReID приведены в
[model-assets.json](../model-assets.json) и [каталоге Open Model Zoo](https://github.com/openvinotoolkit/open_model_zoo/blob/master/models/intel/person-reidentification-retail-0288/model.yml).
План `office.jpg` и калибровки `cam_1_calibration.json` и
`cam_2_calibration.json` входят в репозиторий.

`--start` и `--end` задают секунды на общей шкале экранных часов. Подготовщик
сверяет SHA-256 обоих исходников с аудитом Dima и применяет привязку по участкам.
Без границ обрабатывается вся запись. По умолчанию детекция выполняется на
каждом третьем кадре, а плеер сохраняет исходную частоту видео. `--stride 1`
включает детекцию на всех кадрах. Для нового запуска укажите новый каталог
`--output`.

## Откуда поступают данные

1. Локальный этап пишет `local/office_01/camera_N/frames.jsonl`, кропы и маски.
2. Адаптер Dima читает локальные результаты и вычисляет признаки ReID.
   Сопоставление проверяет взаимные скачки внешности у локальных треков, строит
   исходные группы Dima и уточняет ID по нескольким согласованным кадрам на плане.
   Результат записывается в `global/assignments.jsonl` и `tracks.json`.
   Наблюдения без локального ID остаются в `unassigned.jsonl`. При неоднозначной
   смене личности соответствующая строка назначения получает `global_id: null`.
3. Экспорт связывает назначения по `(camera_id, local_id, frame_index)`,
   проецирует точки опоры на план по гомографиям Fedor и переносит исходное
   видео H.264 в MP4 с сохранением меток кадров. Подписи хранятся отдельно.
4. Сервер читает готовый каталог `session/` с `session.json`, планом и MP4.
   Интерфейс сам запрашивает данные по HTTP. Готовый каталог можно перенести на
   другой компьютер для показа.

Чтобы повторить только экспорт из готового результата Dima, выполните
`.\.venv\Scripts\python.exe -m tools.export_web_session outputs_full/global outputs_reexport/session`.

## Контракт HTTP

| Запрос | Ответ |
|---|---|
| `GET /api/session` | JSON сеанса версии `1.0` |
| `GET /media/map.png` | План в пикселях калибровки |
| `GET /media/camera_1.mp4`, `GET /media/camera_2.mp4` | H.264 MP4 с поддержкой HTTP Range |
| `GET /media/camera_1_overlay.json`, `GET /media/camera_2_overlay.json` | Подписи и рамки по времени исходного видео |
| `GET /docs` | Описание маршрутов FastAPI |

`start_time`, `end_time`, интервалы видимости и `map_path[].t` выражены в
секундах относительно `timeline_origin`. Для камер с `overlay_url` плеер
преобразует общее время в позицию MP4 по `clock_anchors` и `time_offset_sec`.
Файл подписей содержит размеры кадра и массив `[video_time_sec, boxes]`, где
рамка записана как `[global_id, x1, y1, x2, y2]`. Подписи выбираются по времени
фактически показанного кадра. Для готовых старых клипов с вшитыми рамками
позиция плеера равна `t - camera.start`. `coverage` указывает интервалы с видео.

`tracks_summary` индексируется строковым глобальным ID. В каждом треке
`camera_segments` определяет видимость в момент времени, а `map_path` содержит
`t`, `x`, `y`, камеру и статус точки. `x` и `y` измерены в пикселях плана
от верхнего левого угла. Интерфейс рисует оценки пунктиром и разрывает линию
при пропуске. Точки с неизвестной опорой или за границами плана пропускаются.

При отсутствии готового сеанса API возвращает 503, а страница показывает
команду подготовки. Веб-сервер выдаёт только файлы, перечисленные в сеансе.

## Проверка и область работы

Готовая запись камер 1–2 длится около 20:04. В исходных MP4 сохранены 30 083
и 30 077 кадров соответственно. Детекция выполнена на 20 054 кадрах. Из 2 620
локальных наблюдений 19 остались без подтверждённого глобального ID.

На исходном фрагменте камера 2 несколько раз передавала локальный ID другому
человеку. Актуальная ветка Nikita содержит экспорт и привязку оверлея к кадру.
Назначения она читает из Dima. В интеграции использован этот принцип отрисовки
и добавлено исправление смены личности поверх Intel ReID и калибровок Fedor.

На шести вручную проверенных моментах сравнивались одинаковые локальные
наблюдения. Базовый алгоритм правильно связал 5 из 13 пар одного человека
и ошибочно связал 5 из 29 пар разных людей. Новое сопоставление связало
13 из 13 пар одного человека и сохранило разными все 29 пар разных людей.
Выборка включает проблемный момент 199,5 с и эпизоды 539 и 900 с.
Этот результат относится к проверенным кадрам. Полная запись размечена
алгоритмом без сплошной ручной сверки. Для сверки в браузере также проверены
воспроизведение и переход к 1203 с.
