# Сквозной трекинг

Python 3.10+, без внешних зависимостей. Один запуск обрабатывает одну синхронную сессию. Межкамерные связи вычисляются по локальным наблюдениям после обработки видео.

```powershell
python mtmc/associate.py observations.jsonl --config mtmc/camera_graph.example.json --output mtmc-output
```

Перед запуском подставьте реальные `camera_id`, зоны и подтверждённые перекрытия. Числа в примере — начальные пороги для настройки на проверочных фрагментах.

### Вход

Одна строка JSONL — наблюдение человека на конкретной камере. Обязательные поля: `camera_id` (строка), `local_id` (строка или целое), `frame_index` и `timestamp_ms` (неотрицательные целые). Время отсчитывается по общей шкале. Для связки с силуэтами используйте ключ `(camera_id, local_id, frame_index)`. Координаты рамок и маски могут оставаться в исходном файле.

```json
{"camera_id":"cam_a","local_id":17,"frame_index":50,"timestamp_ms":2000,"zone_id":"door_a","embedding":[0.9,0.1,0.2]}
```

Дополнительные поля:

- `embedding` — вектор внешности. Используйте одни веса и одну предобработку на всех камерах. Можно передавать векторы только на выбранных кадрах.
- `hsv` — запасной вектор, например объединённые HSV-гистограммы двух частей силуэта. Используйте одинаковые ячейки гистограммы на всех камерах. Если у обоих треклетов есть `embedding`, сравниваются они.
- `zone_id` — зона наблюдения. Обязательна для передачи между фрагментами без синхронных наблюдений.
- `map_xy` — надёжная точка пола в общей системе координат. `max_map_distance` задаётся в тех же единицах. При `null` геометрия выключена.
- `torso_brightness` — медианная яркость пикселей верхней части силуэта, нормированная к 0–1. Необязательный фильтр `max_brightness_difference` применяется вместе с признаками внешности. По умолчанию выключен.
- `confirmed_global_exit` — `true` только на последнем реальном наблюдении перед подтверждённым выходом из обзора **всех** камер. Сам факт выхода из одного кадра этот флаг не выставляет.

Не включайте в наблюдения позиции, которые локальный трекер только предсказал. `overlap_pairs` — пары камер с совместной видимостью. `continuous_handoffs` — направленные маршруты `[камера_выхода, зона_выхода, камера_входа, зона_входа]` для передачи у общей границы с возможным кратким пропуском детекции. Маршрут через известную слепую зону туда не включается.

### Логика и выход

Локальные фрагменты разделяются по длинным пропускам и подтверждённому выходу. Сначала связываются совместные наблюдения, затем разрешённые передачи. При конкуренции связь должна быть лучшей с обеих сторон и иметь отрыв от второго кандидата. Слияние отклоняется при конфликте интервалов в одной камере, при одновременном наблюдении в камерах без заявленного пересечения или при пересечении подтверждённой границы выхода. Длинное отсутствие не связывается по внешности.

- `assignments.jsonl` — глобальный ID каждого входного наблюдения.
- `tracks.json` — `total_tracks`, список треков, начало и конец по реальным наблюдениям и интервалы по камерам. Интервал группирует близкие по времени наблюдения, исходные кадры перечислены в `assignments.jsonl`.
- `tracks.csv` — одна строка на глобальный трек, с теми же данными.

Модуль принимает готовые признаки. Без признаков или проверенной геометрии межкамерные связи не назначаются. Причину исчезновения из всех камер по одним временным меткам определить нельзя, поэтому для спорных передач используется консервативное правило и нужна проверка на реальных записях.

### Прогон двух роликов `Trim`

Для извлечения наблюдений проверены `ultralytics==8.4.203`, `lap==0.5.14`, `av==17.1.0` и `openvino==2026.4.1` в `mtmc/.venv`. Нужны локальные веса [YOLO11n-seg](https://huggingface.co/Ultralytics/YOLO11/blob/main/yolo11n-seg.pt) и файлы `.xml` / `.bin` [OpenVINO ReID 0288](https://github.com/openvinotoolkit/open_model_zoo/tree/master/models/intel/person-reidentification-retail-0288) из FP32-варианта. ReID возвращает только эмбеддинги. Из корня рабочей папки:

```powershell
$python = './mtmc/.venv/Scripts/python.exe'
& $python mtmc/extract_observations.py `
  --camera 'cam_1=camera_new_1 - Trim.mp4' --camera 'cam_2=camera_new_2 - Trim.mp4' `
  --offset-ms cam_2=1050 --max-seconds 15 --imgsz 960 `
  --config mtmc/camera_graph.pilot.json `
  --weights mtmc/weights/yolo11n-seg.pt --reid mtmc/weights/person-reidentification-retail-0288.xml `
  --output mtmc/pilot-repeat/observations.jsonl
& $python mtmc/repair_local.py mtmc/pilot-repeat/observations.jsonl mtmc/pilot-repeat/observations_clean.jsonl
& $python mtmc/associate.py mtmc/pilot-repeat/observations_clean.jsonl --config mtmc/camera_graph.pilot.json --output mtmc/pilot-repeat
```

Выбирайте новый выходной каталог для повторного извлечения. `repair_local.py` убирает очень короткие локальные треки и объединяет дубликаты ID при совпадении рамок на нескольких кадрах и сходстве эмбеддингов. Поле `source_local_id` сохраняет исходный ID оставленного наблюдения. Для визуализации итоговых ID сопоставляйте `assignments.jsonl` с `observations_clean.jsonl`.

Смещение 1050 мс оценено по смене секунд на наложенных часах в начале роликов. `--max-seconds 15` берёт первые 15 секунд **каждого** файла. Позже у камеры 1 заметна остановка изображения и часов, поэтому для всех 29,6 секунды постоянное смещение не проверено. Прямоугольники `excluded_image_rects` заданы в пикселях исходных кадров вокруг мебели и отражения. Они и пороги `camera_graph.pilot.json` настроены на этом эпизоде. Перед переносом на другие ролики нужны повторная проверка синхронизации и независимый контроль ошибок.

### Сравнение моделей внешности

`compare_reid.py` использует одинаковые кропы из `pilot-aligned/observations_clean.jsonl` и эталонные ID, сверенные на пилотном видео. Сохраните [архитектуру Torchreid](https://github.com/KaiyangZhou/deep-person-reid/blob/master/torchreid/models/osnet.py) как `weights/torchreid_osnet.py`, а [веса OSNet x0.25 MSMT17](https://huggingface.co/kaiyangzhou/osnet/tree/main) как `weights/osnet_x0_25_msmt17.pth`. Из корня рабочей папки:

```powershell
& './mtmc/.venv/Scripts/python.exe' mtmc/compare_reid.py --output mtmc/pilot-aligned/reid-comparison-repeat.json
```

В отчёте есть поиск ближайшего кропа другой камеры, сравнение правильных и ошибочных пар, замеры CPU с предобработкой и подбор порогов по тем же треклетам. Время обработки видео и детекции в замер ReID не входит.

Для `camera_new_1.mkv` и `camera_new_2.mkv` использованы окна со смещением второй камеры на `+900` мс. Извлечение с `--window-ms START END` выбирает общий временной интервал и сохраняет `source_pts` для повторного извлечения исходных кропов. `frame_index` в этом режиме относится к декодированию окна после поиска ключевого кадра. Проверочная разметка и интервалы заданы в `new-comparison/cases.json`, результат в `new-comparison/reid-comparison.json`. Воспроизведение после извлечения окон:

```powershell
& './mtmc/.venv/Scripts/python.exe' mtmc/compare_reid.py `
  --cases mtmc/new-comparison/cases.json --output mtmc/new-comparison/reid-comparison-repeat.json
```

В сравнении использованы только визуально проверенные участки локальных треков. Параметры яркости и сопоставления взяты из пилотной конфигурации. Для фиксированного сравнения выбраны пороги ReID `0.30` для Intel и `0.65` для OSNet по старому пилоту. Эпизоды с одним человеком используются для проверки сохранения ID и скорости. Они исключаются из сводного поиска ближайшего кандидата в сценах с конкурентами.

### Улучшенная стыковка фрагментов

Для нового режима используйте `camera_graph.improved.json`. Исторический `camera_graph.pilot.json` и его поведение сохранены для воспроизводимого сравнения. ReID и детектор не переобучались; используются прежние наблюдения и эмбеддинги Intel 0288.

1. **Восстановление локальных разрывов.** В одной камере сопоставляются концы и начала треков с разрывом до 1500 мс. Проверяются движение вперёд и назад, сходство внешности в секундных окнах у границы и отрыв от конкурентов. Для движения нужен `bbox_xyxy` в одной системе пиксельных координат на протяжении записи. Верхняя часть рамки меньше зависит от скрытых ног. Ошибка движения нормируется на высоту человека, а не на разрешение изображения.
2. **Короткие дубликаты при смене локального ID.** Допускается перекрытие до 100 мс при совпадающих верхних частях рамок и согласованном движении. Продолжительное одновременное наблюдение разных локальных треков в одной камере запрещает объединение. Исходные наблюдения и локальные ID сохраняются, включая два наблюдения на одном кадре у подтверждённого дубликата.
3. **Внешность в общем временном окне.** После прохождения прежнего порога ReID оценка для ранжирования смешивается с оценкой общего интервала. Нужно не менее трёх эмбеддингов с каждой стороны. Трудный ракурс не меняет порог допуска по полному треку.
4. **Пересчёт конкурентов.** После объединения исключаются связи, противоречащие уже собранной группе, и кандидаты ранжируются повторно.
5. **Совместное решение неоднозначных связей.** Если отдельные пары нельзя выбрать уверенно, проверяются совместимые комбинации в небольшом компоненте. Связь принимается, только если её запрет ухудшает лучший общий результат минимум на `min_score_margin`. Равнозначные варианты остаются раздельными. Точный перебор ограничен 12 рёбрами по умолчанию; большие компоненты обрабатываются консервативно, без такого перебора.

Подтверждённый глобальный выход остаётся границей ID. При отсутствии рамок локальная стыковка отключается для соответствующей пары; при отсутствии эмбеддингов не выполняется. Неопределённость сама по себе не считается доказательством совпадения. Короткий реальный выход и возвращение невозможно надёжно отличить от перекрытия без зон выхода, другой камеры или явного `confirmed_global_exit`. Готовый переключившийся ID внутри непрерывного локального трека этот модуль автоматически не исправляет.

Запуск на файле наблюдений из корня рабочей папки:

```powershell
& './mtmc/.venv/Scripts/python.exe' mtmc/associate.py observations.jsonl `
  --config mtmc/camera_graph.improved.json --output mtmc/result-improved
& './mtmc/.venv/Scripts/python.exe' -m unittest discover -s mtmc -p test_associate.py -v
```

Проверка на одинаковых размеченных наблюдениях двух MKV, без повторного запуска нейросетей:

```powershell
& './mtmc/.venv/Scripts/python.exe' mtmc/evaluate_stitching.py `
  --cases mtmc/new-comparison/cases.json --config mtmc/camera_graph.improved.json `
  --output mtmc/new-comparison/stitching-repeat
& './mtmc/.venv/Scripts/python.exe' mtmc/render_comparison.py `
  --cases mtmc/new-comparison/cases.json --config mtmc/camera_graph.improved.json `
  --stitching-report mtmc/new-comparison/stitching-repeat/report.json `
  --timing-note 'Синхронизация требует проверки' `
  --output mtmc/new-comparison/processed-stitched-repeat.mp4
```

Итоговая проверка сохранена в `new-comparison/stitching-v2-verified/report.json`. Эталоны используются только для оценки и выбора ранее проверенных интервалов, значения личностей не передаются сопоставлению. Это набор разработки из четырёх эпизодов, а не независимый тест или оценка полных записей.

| Эпизод | Эталон | До | После | Смешанных треков после |
|---|---:|---:|---:|---:|
| Четыре человека | 4 | 7 | 5 | 0 |
| Два человека в тёмной одежде | 2 | 5 | 2 | 0 |
| Человек в синей куртке | 1 | 1 | 1 | 0 |
| Человек в тёмной куртке | 1 | 2 | 2 | 0 |
| Сумма по отдельным эпизодам | 8 | 15 | 10 | 0 |

Осталось два лишних фрагмента вместо семи. В первом эпизоде белая одежда: разрыв камеры 2 около 2,35 с и недостаточное сходство внешности; в последнем — сходство между камерами ниже порога 0,30. Порог не снижен ради устранения этих ошибок. Старый 15-секундный пилот сохраняет два правильных ID. Проверены 20 сценариев, включая пересечение похожих людей, неоднозначное возвращение, выход, транзитивные конфликты и ограничение перебора. Перемешивание входных строк не меняет назначенные ID, наблюдения не теряются.

**Обнаруженное ограничение синхронизации:** при визуальной проверке нового MP4 во втором эпизоде наложенные часы камер отличаются примерно на 10–11 с, хотя в первом эпизоде совпадают. Следовательно, ранее использованное постоянное смещение +900 мс нельзя считать корректным для всего файла. Видео сохраняет прежние временные окна для сопоставимости результатов. Перед обработкой полной записи нужно проверить часы и построить соответствие времени по участкам, затем заново извлечь и оценить наблюдения. Это ограничение влияет на достоверность предположений об одновременной видимости; показанные числа характеризуют выбранную разметку, а не подтверждают соблюдение непрерывной видимости во всём видео.

### Проверенная привязка часов наших двух MKV

Для `camera_new_1.mkv` и `camera_new_2.mkv` выполнен полный проход по 60 160
кадрам. Установлены два скачка PTS примерно по 10 секунд в каждом файле,
в разных местах. Постоянное смещение +900 мс заменено плотной привязкой
по экранным часам с отдельными опорами у скачков. Готовая конфигурация —
`local_stage.synced.yaml`, карта и SHA-256 источников — `sync-check/alignment.json`.

Подробности и ограничения: [sync-check/README.md](sync-check/README.md).
`render_synced.py` формирует полную запись либо короткие эпизоды с заново
вычисленными ID из `process_synced_demo.py`. Это выравнивание по OSD;
аппаратная кадровая точность не подтверждена. Старые видео сохранены отдельно,
их постоянное смещение не исправлено задним числом.
