# Повторное обучение: отражения

Проблема воспроизведена по `outputs_occlusion_full/office_01/camera_3/frames.jsonl`:
исходный кадр **4026**, `video_time_sec=157.83`, общее время `159.69386` секунды.
У отражения local=17 уверенность 0.9565. Только **62.38%** его сохранённой маски
находится в полигоне `curved_mirror`, поэтому прежнее условие 85% его пропускало.
У двух проверенных физических людей пересечение с зеркалом равно нулю.

Для камеры 3 порог доли маски в напольном зеркале изменён на **60%**. Регрессионный тест
использует уменьшенные контуры трёх реальных обнаружений этого кадра: старое
условие сохраняет все три, исправленное удаляет отражение и сохраняет двух людей.
Входной кадр не закрашивается. Человек, большей частью перекрывающий зеркало
в проекции, всё ещё может быть ошибочно исключён: геометрическая зона сама
по себе не различает отражение и физический объект перед зеркалом.

В дальнем коридоре камеры 3 также отражаются люди в стеклянных панелях над
открытой дверью. Добавлена отдельная зона `corridor_glass_reflections` с порогом
85%. Тесты проверяют отражение кадра 4026 и сохраняют настоящего человека
за открытой дверью. Эти панели не были покрыты прежним полигоном напольного зеркала.
На кадре 4154 маска отражения пересекается с зоной на 84.95% и проходит фильтр.
Её confidence=0.4766 ниже текущего нижнего порога ByteTrack 0.50, поэтому ID
не присваивается. По уточнению пользователя такой диагностический кандидат
допустим; ужесточение зоны ради него отменено. Тест проверяет сохранение
`local_track_id=null` при текущих порогах трекера.

из всех обучающих масок без разбора. Негативные примеры задаются отсутствием
положительной метки у отражения или изображения на экране.

исправленных метках. Контроль на одной записи всё равно не оценивает обобщение
на новые помещения, личности или записи. Порог зеркала исправлен по
предоставленному примеру; тест не является независимым для этого порога.

## Обучение и воспроизведение

Первый вариант обучен от официальной YOLO11s-seg: 50 эпох, 341 с по results.csv,
imgsz=640, batch=2, freeze=10, AdamW, lr0=0.0003, FP32, seed=42, без отражения
кадров по горизонтали. Файлы — `runs/mirrors/person_v2`, резервные веса —
`weights/person-office-v2-fresh.pt`. Он исключил зеркальные FP на контрольных
кадрах, но снизил полноту на val с 60/64 до 56/64 при confidence=0.25.
Его вариант с входом 640 не выбран для основной конфигурации.

Проверен и вариант продолжения v1: lr0=0.0001, 20 эпох, patience=8,
без mosaic. При входе 640 он тоже терял далёких людей, поэтому не выбран.

Финальное уточнение начато от `person-office-v2-fresh.pt` после удаления двух
ошибочных меток дальних отражений: **10 эпох, imgsz=800, batch=2, lr0=0.00003,
freeze=10, без mosaic и без прогрева learning rate**. Каталог обучения —
`runs/mirrors/person_v2_refined`; выбраны веса `best.pt` по валидации.
Увеличение входа проверено на val: размер 640 терял небольшие фигуры, а 960
добавлял больше ложных кандидатов. Рабочий размер — **800**, confidence **0.25**.
Уточнение заняло 93 с по results.csv. Исходные координаты видео и экспортируемых
масок остались в разрешении 2592×1944; поменялся только внутренний вход модели.
Обучение и оценка выполняются локально на RTX 5060; базовые веса и зависимости
уже присутствуют в окружении.

```powershell
.\.venv\Scripts\python.exe tools/retrain_mirrors.py prepare
# Визуальная проверка candidates.json и листов review_*.jpg обязательна.
# Решения и контрольные суммы хранятся в configs/mirror_annotation_review.json.
.\.venv\Scripts\python.exe tools/retrain_mirrors.py build
.\.venv\Scripts\python.exe tools/retrain_mirrors.py train-refined
.\.venv\Scripts\python.exe tools/evaluate_mirrors.py weights/person-office-v1.pt --imgsz 640
.\.venv\Scripts\python.exe tools/evaluate_mirrors.py weights/person-office-v2.pt --imgsz 800
```

Подготовка и сборка отказываются перезаписывать готовый датасет. Для повторения
на текущей машине используйте готовый датасет, а не запускайте подготовку заново.
При новом извлечении кадров/смене учителя контрольные суммы могут измениться:
разметку нужно проверить снова, а не обходить проверку хеша.

Оценка сравнивает рамки с разметкой при IoU ≥ 0.5, confidence=0.25, исходном
imgsz=640 для v1 и рабочем imgsz=800 для v2,
FP16. Отдельно сохраняются результаты чистой сети и сети с фильтрами сцены.
`mirror_fp` — диагностическая подгруппа несопоставленных обнаружений, у которых
не менее 30% маски находится в отражающей зоне; она не меняет правила сопоставления.
В обеих колонках с фильтрами используется одна исправленная конфигурация зон.
Детальные результаты находятся в `data/person_mirrors_v3/*_mirror_evaluation.json`.

На этих 76 кадрах зеркальные FP самой сети уменьшились с **6 до 0**,

все остальные ошибки и не даёт безусловного улучшения точности на всех сценах.
Геометрические фильтры оставлены как дополнительная защита.
